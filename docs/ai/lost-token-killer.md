# Lost Token Killer (Codex 版)

Claude Code スキル `lost-token-killer` を Codex CLI 向けに移植した運用ルール。
目的は品質を落とさずに **再読・再生成・冗長出力・無駄往復・過剰思考** の5つの
ロストを潰すこと。

## 発動方法

Claude Code のスキルは description による自動発動だが、Codex にその仕組みはない。
このリポジトリでは次のどちらかで発動する。

- ユーザーが「LTK」「節約モード」「軽く進めて」と言う
- 同一ファイルへの修正が3回以上続く、または会話が長くなってきたと判断したとき

発動したら冒頭に一行だけ宣言する:

`LTKモードON（結論ファースト・差分編集・一行報告で進めます）`

## 1. 再読ロスト

同じ内容を何度も読まない。

- `rg -n <pattern>` で行位置を特定してから `sed -n '120,160p' <file>` で必要な範囲だけ読む
- ファイル全体の読み込みは初回のみ。全文再読は最終レビュー時と編集競合時だけ許可
- 一度読んだ内容は要約をテキストで持ち回る。画像・スクリーンショットの再確認は禁止
- コンテキストが厳しくなったら `/compact` を先に打つ。上限に当たってからの自動圧縮より安い

## 2. 再生成ロスト

ファイルを丸ごと書き直さない。

- 既存ファイルの修正は `apply_patch` の差分ブロック（`@@` + `-` / `+`）で行う
- `*** Add File` は本当に新規のときだけ。既存パスへの全文上書きは禁止
- 「全面的に作り直して」と明示されたときのみ再生成してよい
- 複数箇所の修正は1回の `apply_patch` にまとめる（往復を減らす）
- 検証スクリプトは初回に1本書いて使い回す。毎回新規作成しない

## 3. 冗長出力ロスト

返答とコードを長くしない。

- 返答は結論ファースト、3〜6文以内。変更内容の全文引用はせず要約のみ
- コードをチャット本文に貼らない。ファイルに書いてパスを示す
- 検証結果は「OK / NG + 一行理由」形式
- 絵文字・装飾・表は最小限。箇条書きは要点のみ
- 提案・レビュー系も同じ。選択肢は最大3つ、各1〜2行

## 4. 無駄往復ロスト

確認と質問で1往復を浪費しない。

- 「追記しますか？」と聞かない。必要と判断したら実行して結果を一行報告する
- ただし `AGENTS.md` の Safety and Publishing に該当する操作（公開、削除、URL移行、
  権限変更、本番マージ）は必ず事前確認する。ここは節約より優先
- 曖昧な指示はリポジトリの既存文脈から補完して進め、置いた仮定は報告に一行添える
- 返答末尾に「他に直す点があればまとめてどうぞ」を添えて細切れ指示を防ぐ
- ツールやファイルの存在確認は1コマンドで済ませる（`ls` → 判定 → 報告を1ターン）

## 5. 過剰思考ロスト

推論エフォートを使いすぎない。Codex では設定で直接制御できる。

- 定型作業（差分修正、ファイル移動、一行報告）は `model_reasoning_effort = "low"`
  相当で即実行する。深い思考を挟まない
- 設計判断・トレードオフ検討は初回の1回に集中させ、以降は決定に従って機械的に実行
- 一度決めた方針（構造・命名・技術選定）は決定事項として扱う。再検討はユーザーが
  変更を指示したときだけ
- 可逆な操作（差分編集、ファイル生成）は考え込むより実行して結果で判断する

エフォートの切り替えは `/model` から行う。セッション既定は `~/.codex/config.toml` の
`model_reasoning_effort` で設定する。

## セッション運用

- 修正が細切れに来そうなときはバッチ指示を促す（1往復は固定コスト）
- 中間修正では対象箇所のスモークチェックのみ。`./scripts/verify.sh` のフル実行は
  サインオフ直前に1回
- スクリーンショット検証は要求されたときだけ。既定はログとファイル内容での検証
- 大きな構想はまず計画 Markdown を1ファイルに固め、実装ターンでは対象セクションだけ読む
- 繰り返し使う運用ルールは会話で説明せず `AGENTS.md` と `docs/ai/` に固定する

## 出力フォーマット

```
修正完了: <変更点を1行>
変更箇所: <ファイル名> L120付近（○○を△△に）
未検証: <あれば1行、なければ省略>
```

複数修正をまとめた場合:

```
3件修正完了: <要約1行>
1. <1行>
2. <1行>
3. <1行>
```

## 適用しない場合

- 初回の設計提案や要件定義など、思考の幅が価値になる場面
- ユーザーが「詳しく説明して」と明示した場合
- 安全性・正確性に関わる確認（削除、上書き、公開、課金操作）

## シェル層の圧縮（任意）

このドキュメントはプロンプト層のルールで、シェル出力そのものは削減しない。
`git diff` やテスト出力が重い場合は、出力を圧縮する CLI プロキシを併用できる。

- [rtk-ai/rtk](https://github.com/rtk-ai/rtk) — Apache-2.0。`rtk init -g --codex` で
  `AGENTS.md` + `RTK.md` に導入手順が書き込まれる
- 効果はワークロード依存で、低エフォート時は逆に増えたという計測報告もある。
  導入する場合は自分のセッションで前後比較してから常用する

## 元スキルとの差分

移植にあたり Claude Code 固有の記述を次のように置き換えた。

| 元スキル（Claude Code） | Codex 版 |
| --- | --- |
| description による自動発動 | ユーザー指示または判断による明示発動 |
| `view` / `view_range` | `rg -n` で位置特定 → `sed -n 'X,Yp'` |
| `str_replace` | `apply_patch` の差分ブロック |
| `create_file` での全文再出力 | `apply_patch` の `*** Add File`（新規時のみ） |
| `present_files` | ファイルパスの提示 |
| Fable / Opus / Sonnet の使い分け | `/model` と `model_reasoning_effort` |
